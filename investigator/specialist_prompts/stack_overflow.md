Inspect stack-allocated buffers and writes in the scoped native code or binary. Trace input origin, maximum size, allocation size, copy or format operation, and guards. A dangerous API name alone is not a finding. Use the write site as the root-cause location and record exact source line or disassembly offset. Distinguish a possible stack overwrite from stack exhaustion by recursion. If the bounds and reachability are proven statically, static_verified may describe the code weakness without claiming exploitation. Use needs_dynamic_verification when actual input reachability, overwrite, or crash requires a controlled local test. Put crash or DoS in impact_tags rather than opening a duplicate DoS finding.
